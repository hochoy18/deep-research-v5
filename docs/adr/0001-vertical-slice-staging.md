# ADR 0001 — 垂直切片阶段策略

- 状态: 已采纳
- 日期: 2026-10-19

## 背景

Deep research agent 有三层 (Plan / Research / Write), 而且各层都有跨层关切 (HITL 在 Plan; 评估在 Research 与 Write 两层都有)。从一开始就出现三条互相正交的加深轴: HITL 丰富度、评估深度、报告润色度。

## 候选方案

### 按层切 (P1 = Plan, P2 = +Research, P3 = +Write)
- 每个阶段最容易定范围。
- 用户要到 P3 才能感受到 "完整的 deep research"。
- Eval 与 HITL 模式跨多层, 设计会延后到后期。

### 混合 (P1 = Plan + 手工 research, P2 = research 自动化, P3 = write)
- 第一次可用 research 稍快。
- 仍然卡在同样的阶段瓶颈 — 完整形态要等到 P3 才会出现。
- Plan 与 Research 强耦合; 硬切开, 等到 P2 启动时容易 churn。

### 垂直切片 *(被采纳)*
- 每个阶段交付三层的一个薄切片。
- 每个阶段都能 demo 一次完整流程。
- 每层的第一个版本会更糙。

## 决策

按 **垂直切片** 节奏发布里程碑。**P1** 是 Plan → Research → Write 三层的最薄端到端版本。后续阶段专注于 **加深** (例如: Plan 的 HITL 更丰富、Research 的评估更深、Write 的多遍润色), 而不是横向铺开新的层。

## 影响

+ 每个阶段都有完整 demo。
+ 跨层关切 (HITL、eval、citation 交接) 从 P1 起就被串联到。
+ 各层不会在设计上跑偏 — 每个阶段每一层都会被实际用到。
− 每个层每个阶段的加深深度被限制。
− 每个阶段的工作预算相对恒定 (每阶段都动到三层); 某一层想大幅升级, 得跨多个阶段规划。
− P1 的深度比 "按层切 P1" 浅 — 是有意识的取舍。
